## Purpose

定义 Agent-Inspect 以一次进程内调用即可启用、自动唤起本地调试面板,并在本机内嵌服务与本地存储,无需部署独立服务或外置后端即可使用的可观测行为。

## ADDED Requirements

### Requirement: 一次调用启用
系统 SHALL 以一次进程内调用同时启用拦截与本地调试面板,无需额外启动步骤。

#### Scenario: 一行启用全套
- **WHEN** 调用启用入口
- **THEN** 拦截、决策点记录与本地调试面板同时就绪,无需运行第二条命令或启动额外服务

#### Scenario: 面板就绪后立即可调
- **WHEN** 启用入口返回
- **THEN** 本地面板已可接收并展示其后 Agent 的决策点

### Requirement: 自动唤起本地面板
系统 SHALL 在启用后自动打开本机浏览器至本地调试面板地址。

#### Scenario: 自动开浏览器
- **WHEN** 启用入口在具备图形环境的本机执行
- **THEN** 默认浏览器被自动打开至本地调试面板地址

#### Scenario: 无头环境降级
- **WHEN** 启用入口在无图形或无浏览器可用的环境执行
- **THEN** 系统不报错,改为将本地调试面板的可访问地址输出,供人工或脚本打开

### Requirement: 本机内嵌服务
系统 SHALL 在同一进程内托管调试面板与决策点收发,不要求独立部署的调试服务。

#### Scenario: 进程内自托管
- **WHEN** 启用入口运行
- **THEN** 调试面板的页面与决策点接口由同进程内嵌服务提供,不存在独立调试服务进程

#### Scenario: 端口冲突自适应
- **WHEN** 默认本地端口已被占用
- **THEN** 系统自动选择一个可用本地端口并据此打开面板

### Requirement: 实时双向消息
系统 SHALL 与面板维持实时双向消息通道,使其可展示执行中决策点并接收调试指令。

#### Scenario: 决策点实时推送
- **WHEN** Agent 执行中产生新决策点
- **THEN** 面板在不刷新的情况下实时收到并追加这些决策点

#### Scenario: 调试指令实时下发
- **WHEN** 面板发出 Fork、修改或继续等调试指令
- **THEN** 该指令实时送达执行侧并影响后续决策点行为

### Requirement: 零外置后端可用
系统 SHALL 不依赖外部数据库或独立后端即可完整提供其 MVP 行为,数据存放于本地。

#### Scenario: 无外置后端运行
- **WHEN** 启用入口运行且本机无任何外部数据库
- **THEN** 决策点的记录、回放与 Fork 均可正常工作,数据持久化于本地文件

#### Scenario: 进程退出后历史留存
- **WHEN** 进程退出后再次启用并查询先前 trace
- **THEN** 先前持久化的决策点仍可被读取用于回放与 Fork

### Requirement: Trace 生命周期
系统 SHALL 为每条 trace 维持一个可观测的生命周期状态,使面板与后续操作能区分进行中、完成与异常中止。

#### Scenario: 完成态标记
- **WHEN** 一条 trace 的目标 Agent 执行结束且不再产生决策点
- **THEN** 该 trace 被标记为完成,后续可按完成态筛选与回放

#### Scenario: 异常中止标记
- **WHEN** Agent 执行因错误或中止而提前结束
- **THEN** 该 trace 被标记为异常中止,保留已产生决策点并区别于完成态

#### Scenario: 查询带生命周期筛选
- **WHEN** 调用方按生命周期状态查询 trace
- **THEN** 返回符合该状态(进行中、完成、异常中止)的 trace 列表
