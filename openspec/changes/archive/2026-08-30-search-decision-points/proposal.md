# search-decision-points

## Why

链路一长(几十个决策点的复杂 Agent、多轮 ReAct),现在的面板只能**逐点翻看**——"哪一步提到了 XX?"、"上次报错前模型看到了什么?"这类最自然的调试问题没有入口。Live 调试的断点条件已经支持"输入含子串命中",但那要求**预知**关键字并在**下一次运行**时生效;对已记录链路的回溯检索是空缺。

本 change 补上**按内容搜索决策点**:在一条 trace 的全部分支内,按子串(大小写不敏感)检索决策点的完整输入与输出,返回命中位置与上下文片段,面板点击命中直接定位到该决策点。与断点条件互补:断点是"下一次运行时拦",搜索是"已记录链路里找"。

范围克制:子串匹配(大小写不敏感),不做正则/语义检索;只搜单条 trace(全局跨 trace 搜索推迟);本地规模线性扫描,不建索引。

## What Changes

- **后端(新增 `agent_inspect/search.py`)**:`search_trace(store, recorder, trace_id, query)`——遍历该 trace 的每个分支,经既有解析层还原完整输入输出,序列化后做大小写不敏感子串匹配;命中返回 `{branch_id, step_index, kind, agent_id, matched_in: "input"|"output", snippet}`(snippet 为命中处前后约 60 字符的上下文片段);结果按分支与步骤排序。
- **API**:`GET /api/traces/{trace_id}/search?q=<文本>` → 200 命中列表;trace 不存在 404;`q` 缺失 422。
- **UI**:工具栏加搜索框——输入即搜(轻量防抖),结果浮层列出命中(kind 徽标 + 步骤号 + 命中来源 + 片段);**点击命中 → 面板定位**:必要时切换到命中所在分支,选中该决策点(右侧显示完整输入输出,链上高亮);清空查询即收起。
- **spec**:新增 `trace-search` 能力(内容搜索 / 面板入口)。
- **测试**:搜索单测(输入命中/输出命中/大小写不敏感/无命中/多分支排序)、API e2e(命中/404/422)。

## Out of scope

- 跨 trace 全局搜索(端点天然可扩展,留作后续);正则与语义检索;搜索索引(本地单文件规模线性扫描足够);输入内嵌工具结果的递归深搜(完整解析后的序列化文本已覆盖常规场景)。

## Criteria

- 对已记录 trace 提交查询后,凡输入或输出包含查询串(忽略大小写)的决策点都出现在结果中,标注所在分支、步骤、命中来源与上下文片段;
- 无命中返回空集;trace 不存在 404;查询缺失 422;
- 面板输入查询即出结果列表,点击命中后面板定位到该决策点(必要时自动切换分支)并显示完整输入输出;清空查询收起结果;
- 全量测试通过,零回归。
