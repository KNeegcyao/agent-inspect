# Agent-Inspect 并排分支 diff — 提案

## Why

Replay / Fork / Live 已让开发者能**产生**多条分支,但"看分支"还停在零散对照:面板只有两列并排 + 前端按输出序列化比对出"哪些步骤不同"的集合,给不出**改了什么、在哪一步、哪个字段**。Fork 的传播爆点恰恰是"同一棵树、两条分支并排,用户改一个值,世界分叉"——要讲清这个故事,需要把分支差异做成**精确、可读、字段级**的对照:`openspec/config.yaml#context` 已确立"分支图可枚举与并排",本 change 让"并排"从两列画布升级为真正的 diff(对齐步骤 + 相同/差异/仅一侧 + 字段明细 + 汇总)。

## What Changes

- 新增 **branch-diff** 能力:对同一 trace 下任意两个分支,按决策点对齐,给出每个步骤的对照状态(**相同 / 差异 / 仅左侧 / 仅右侧**);差异步骤给出**字段级明细**(输入与输出内具体路径的左右取值,或仅一侧有该字段);一次比较给出**汇总计数**。
- 面板**并排呈现**两分支决策链,按 diff 结果区分节点(相同/差异/仅一侧);选中差异步骤展示字段级明细,供"改了一刀,世界在哪分叉、怎么分叉"精确阅读。

## Capabilities

- **New Capabilities**
  - `branch-diff` — 分支对齐、步骤状态、字段级明细、汇总计数、并排视图呈现。
- **Modified Capabilities**
  - (none — 既有能力契约不变;trace-ui 的并排枚举行为沿用,本 change 在数据与呈现上扩展)

## Impact

- 代码:后端新增只读 diff 引擎(完整链路构造 + 对齐 + 字段 diff)+ 只读接口;前端 `api.js` 增加 diff 客户端,`App.jsx` 以 diff 结果替换原 divergentSteps 推导并注入两列画布,`ChainCanvas` 按状态着色,新增差异明细面板。
- 测试:diff 引擎单测(对齐/相同/差异/仅侧/字段路径/嵌套/深度上限/汇总)、e2e(diff 接口返回对齐步骤与字段明细)、零回归(既有 record/replay/fork/live 用例)。
- 依赖:不新增外部依赖。
- 兼容:diff 为只读计算,不落库、不改既有数据;未选择对比分支时零影响。

## Out of Scope (Non-Goals of this change)

- 工具返回值注入、大上下文增量快照 + 高速渲染(Phase 2 其余条目,另立 change)。
- 跨分支内容合并/同步(把一侧字段写回另一侧)——归入后续"分支编辑" change。
- 语义级 diff(字段位置漂移、重命名识别)——当前为逐字段结构 diff。
- 决策点间的子图结构 diff(因果边拓扑比较)——当前按步骤索引线性对齐。

## Open Questions

- Q1(建议):对齐键定为**步骤索引**(两分支共享前缀天然同号)。**默认采用**;若后续需要按因果边拓扑对齐,另立 change。
- Q2(建议):差异判定以**输出**为主(同号异输出 → 差异),但字段明细**同时覆盖输入与输出**(改了输入、输出仍相同也值得看到)。**默认采用**。
