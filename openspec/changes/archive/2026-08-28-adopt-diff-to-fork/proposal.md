# adopt-diff-to-fork

## Why

`compare-traces` 已能跨 trace / 跨分支并排 diff,把两条运行逐步骤、逐字段对照出来。但对比只停在"看"的层面:当用户在 diff 中发现另一侧(对比分支)有更好的 prompt / 参数 / 工具返回时,无法把它一键变成对自己分支的修改并真实执行看效果。当前只能手动把差异字段逐个填进 Fork 面板,费力且易错。

本 change 打通「diff → fork」:在并排 diff 的差异步骤上,一键把「右侧(对比分支)的差异字段」采纳为「对左侧(主分支)的 Fork 修改」,生成新分支真实执行。这一步把**主动分叉试验**与**跨运行对照**两个能力焊接起来:看到差异 → 采纳 → 亲验其影响。

上一 change `compare-traces` 的 out-of-scope 明确列出"跨 trace 分叉/采纳(diff → fork 应用)"作为后续 change,本 change 正是承接它。

## What Changes

- **后端**:新增采纳入口,复用 diff 引擎算出对比分支(右侧)与主分支(左侧)的字段级差异,并把差异映射为一组 Fork 修改(`Modification`):
  - `input_context.*` 差异 → 以右侧值替换该决策点输入(注入后真调),映射为 `input_context.<path>` 修改;
  - `output` 差异 → 以右侧输出整段覆盖(注入工具/模型返回),映射为 `output` 修改;
  - 提供只读预览档(dry_run)返回将应用的修改列表,不落库、不真调。
- **UI**:BranchDiffView 每个差异步骤(或整体)提供「采纳到 Fork」入口,展示将应用的修改清单,确认后复用现有 Fork 面板流程创建新分支。
- **测试**:采纳修改生成的映射正确性(输入/输出路径、列表索引)、预览不落库、采纳后创建新分支并真实执行、错误路径(同类控制器校验)。

## Out of scope

- 对 `only_left` / `only_right`(仅一侧存在)步骤的合并采纳 —— 无另一侧值可采纳,需专门的空位填补语义,后续 change。
- 半自动合并 / 三向合并(diff → 组合多条采纳再一次性应用)。
- 修改了 Fork 引擎对修改类型的表达能力(仍限 input/output 两类)。

## Criteria

- 能从一个跨 trace diff 的差异步骤,一键把对比侧的字段差异转为对主分支的修改。
- 预览(只读)明确列出将应用的修改路径与值,不改动任何已存分支。
- 确认后创建新 Fork 分支,按注入的后缀真实执行,可查看其后续演化。
