# js-sdk Specification

## Purpose
为 JavaScript 运行时的 Agent 提供与既有能力等价的交互式调试:一行启用本机内嵌面板,自动把 LLM 调用记录为决策点,支持从面板发起反事实 Fork——前缀用记录输出确定性回放、注入修改、后缀真实执行。未启用时对宿主程序零影响。

## Requirements

### Requirement: JavaScript 运行时一行启用

系统 SHALL 提供 JavaScript 运行时的一次调用启用方式:启用后本机内嵌面板以既有契约可访问,宿主 Agent 的 LLM 调用开始被记录;未启用时零行为变化。

#### Scenario: 一行启用后面板可用且开始记录

- **WHEN** JS 程序调用一次启用
- **THEN** 本机内嵌面板可访问,同一 REST/SSE 契约可查询;此后 JS Agent 的 LLM 调用被记录为决策点,实时出现在面板

#### Scenario: 未启用零行为变化

- **WHEN** JS 程序不调用启用
- **THEN** 宿主程序行为与无本系统时完全一致:不产生记录、不拦截调用、不监听端口

### Requirement: 自动拦截 LLM 调用为决策点

系统 SHALL 把 JS Agent 的 LLM 调用自动包装为决策点:完整输入输出落库,顺序因果边相接。

#### Scenario: 记录完整输入输出

- **WHEN** JS Agent 发起一次 LLM 调用
- **THEN** 生成一个 llm 决策点,其输入(消息列表、模型、参数)与输出可经面板读取,内容与真实调用一致

#### Scenario: 多步因果链

- **WHEN** JS Agent 顺序发起多次 LLM 调用
- **THEN** 决策点按 0 起编号,每个决策点的因果边指向前一个,面板链路按序呈现

### Requirement: 面板发起 Fork 并真实重跑后缀

系统 SHALL 支持经面板对已记录链路发起 Fork(起点步骤、注入修改、只读预览、备注),由同进程内 JS Agent 的下一次执行消费:起点之前回放记录输出,起点之后真实执行。

#### Scenario: Fork 创建与消费

- **WHEN** 经面板对已记录链路的某决策点发起 Fork,随后同进程内 JS Agent 再次执行
- **THEN** 该次执行进入新分支:起点之前的决策点回放记录输出(不发起真实调用),起点起的决策点真实调用并记录到新分支

#### Scenario: 注入输入修改生效

- **WHEN** Fork 携带输入路径修改(如消息内容)
- **THEN** 该决策点以修改后的输入真实调用,落盘输入为修改后的值

#### Scenario: 注入输出不真调

- **WHEN** Fork 对某决策点携带输出整段替换
- **THEN** 该决策点不发起真实调用,注入值直接生效并落盘

#### Scenario: 只读预览不真调

- **WHEN** Fork 以只读预览方式发起并执行
- **THEN** 后缀所有决策点均不真实调用,输出为空,不产生真实副作用

#### Scenario: 非法 Fork 拒绝

- **WHEN** Fork 起点越界、或目标链路没有任何决策点
- **THEN** 拒绝并给出可观测原因,不创建分支

### Requirement: 面板契约一致

系统 SHALL 复用既有面板与契约的所需子集:链路查看、决策点详情、Fork 表单、分支对比(含跨链路)在 JS 运行时下行为一致。

#### Scenario: 面板能力可用

- **WHEN** 打开 JS 运行时的内嵌面板并选中一条链路
- **THEN** 决策链呈现、决策点详情、Fork 发起、分支并排对比(含跨 trace)均可用

### Requirement: JavaScript 运行时 Live 调试

系统 SHALL 在 JS 运行时提供与既有能力等价的 Live 调试:附加运行中的 Agent,按类型或输入内容设断点,命中后暂停(完整输入可查),支持单步、暂停点替换输入后继续;调试指令绑定暂停点,重复投递不误放后续暂停点。

#### Scenario: 附加并命中断点暂停

- **WHEN** JS Agent 运行中,面板附加并按类型设断点,随后 Agent 到达首个匹配的决策点
- **THEN** 执行在该决策点边界暂停:该点的完整输入可查,Agent 在放行前不发起真实调用;未匹配的决策点不受影响

#### Scenario: 单步与改输入继续

- **WHEN** 暂停后发出单步,再对暂停点提交输入替换并继续
- **THEN** 单步恰执行一个决策点后在新暂停点停下;替换后的输入被真实调用使用并落盘;继续后运行至完成

#### Scenario: 重复投递幂等

- **WHEN** 释放类指令(单步/继续)携带发起时的暂停点重复或迟到投递
- **THEN** 与当前暂停点不匹配的指令被忽略,不跳过任何暂停点

#### Scenario: 断点持久化与作用域隔离

- **WHEN** 设置断点后重启会话,或同时运行另一条未设断点的 trace
- **THEN** 断点跨会话保留并继续生效;断点只影响其所属 trace,其它 trace 零感知

### Requirement: JavaScript 运行时副作用沙箱

系统 SHALL 允许在 JS 运行时发起 Fork 时按决策点类型配置副作用策略(allow / dry-run / block),隔离 Fork 后缀的真实副作用;未配置的类型保持真实调用,非法配置拒绝且不落库。

#### Scenario: 按 kind 配置策略

- **WHEN** 发起 Fork 时携带 sandbox 配置(`{kind: policy}`)
- **THEN** Fork 后缀中命中类型的决策点按策略执行:dry-run 与 block 不发起真实调用并标记,allow 或未配置的类型照常真实调用

#### Scenario: dry-run 模拟

- **WHEN** 某类型配置为 dry-run 后执行 Fork 后缀
- **THEN** 该类型决策点不发起真实调用,输出为空,meta 标记模拟

#### Scenario: block 阻止

- **WHEN** 某类型配置为 block 后执行 Fork 后缀
- **THEN** 该类型决策点不发起真实调用,meta 标记阻止

#### Scenario: 非法配置拒绝

- **WHEN** sandbox 中出现未知类型或未知策略
- **THEN** 拒绝创建 Fork 并给出可观测原因,不产生任何新分支

### Requirement: 导入与推送

系统 SHALL 在 JS 运行时提供外部 span 导出 JSON 的导入(与既有导入语义一致:两形态、按类型映射、非法拒绝不落库)与链路推送到用户收集端点的能力;两者均可经面板使用。

#### Scenario: 导入为可调试链路

- **WHEN** 经面板或 API 提交合法的 span 导出 JSON
- **THEN** 生成与自录同构的 trace(LLM/工具决策点、顺序、因果边、完整输入输出),非法导出返回 422 与可观测原因且不落库

#### Scenario: 推送链路到收集端点

- **WHEN** 对一条 trace 指定收集端点发起推送
- **THEN** 链路以与导出一致的映射送达端点(载荷经包装协议传输);成功回报送达统计,失败给出可观测原因且不改动本地数据
